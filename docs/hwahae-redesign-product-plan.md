# BE:CAUSE — 화해 리디자인 통합 서비스 기획안

> Version 1.0 · 2026-08-27  
> 대상: 모바일 앱 + 반응형 웹사이트  
> 성격: 공식 의뢰 여부가 확인되지 않은 비공식 UX/UI 리디자인 콘셉트

## 0. 기획 결론

이 프로젝트는 화해의 화면을 단순히 새로 꾸미는 작업이 아니다.

화해가 이미 갖고 있는 **리뷰·성분·랭킹·쇼핑의 신뢰 자산** 위에, 기존 BE:CAUSE 프로젝트의 **피부 맥락·환경 데이터·성분 해석·루틴·비교·대화형 도움**을 하나의 구매 의사결정 흐름으로 통합한다.

새로운 서비스가 해결할 핵심 질문은 다음 한 문장이다.

> “이 제품이 인기 있는지는 알겠는데, 지금의 내 피부와 루틴에 왜 맞거나 맞지 않는가?”

제품 방향은 **화장품 정보 플랫폼에서 개인 뷰티 의사결정 운영체제로의 확장**이다.

사용자 경험은 `찾기 → 믿기 → 비교하기 → 구매하기 → 사용하기 → 기록하기`가 끊기지 않도록 설계한다.

## 1. 프로젝트 재정의

### 1.1 프로젝트명

- 외부 표기: **BE:CAUSE — unofficial Hwahae redesign concept**
- 내부 제품명: **Project BE:CAUSE**
- 분석·개인화 엔진명: **BE:CAUSE Insight**
- 대화형 도우미명: **Remi / 레미**

BE:CAUSE는 사용자가 제품 선택 근거를 이해하도록 돕는 분석·개인화 레이어이자 이 비공식 리디자인 프로젝트의 제품명이다. 공식 협업이나 상표 사용 허가가 확인되기 전까지 모든 외부 결과물에는 `Unofficial redesign concept`를 표기한다.

### 1.2 리디자인 목표

1. 방대한 제품·리뷰·성분 정보를 사용자의 상황에 맞는 결정 근거로 압축한다.
2. 랭킹과 추천의 이유를 숨기지 않고 데이터 출처와 기준을 설명한다.
3. 제품을 사기 전뿐 아니라 구매 후 루틴과 피부 기록까지 연결한다.
4. 모바일은 빠른 탐색과 기록, 웹은 깊은 비교와 리서치에 최적화한다.
5. 광고·협찬·체험단·실구매 리뷰를 시각적으로 명확하게 구분한다.

### 1.3 하지 않을 것

- 화해의 화면을 그대로 복제하지 않는다.
- 근거 없는 `96% MATCH`처럼 점수만 단독 노출하지 않는다.
- 성분 포함 여부만으로 완제품의 효능을 단정하지 않는다.
- AI를 의료 진단이나 처방처럼 표현하지 않는다.
- 공식 허가 없이 화해의 리뷰·상품 이미지·랭킹 데이터를 수집하거나 재배포하지 않는다.
- 모바일 화면을 그대로 늘여 웹 화면으로 사용하지 않는다.

## 2. 현재 서비스 기준선

2026-08-27 공식 웹과 앱 소개에서 확인한 화해의 주요 축은 다음과 같다.

- 제품 리뷰, 성분 정보, 랭킹, 쇼핑
- 피부 타입·고민·리뷰 기반 궁합 점수
- AI 기반 사용 제품 진단
- 카테고리·피부 타입·나이대별 랭킹
- 샘플 체험
- 위치 기반 날씨 확인
- 급상승 제품 및 브랜드 탐색

따라서 `성분 + 리뷰 + 맞춤 추천` 자체는 새로운 차별점이 아니다. 이번 리디자인은 **정보를 제공하는 것보다 사용자가 결정을 검증하도록 만드는 것**에 초점을 둔다.

### 2.1 현재 단계에서 모르는 것

- 화해 내부의 실제 추천·랭킹 산식은 모른다.
- 화해의 공식 제품·리뷰 공개 API는 확인되지 않았다.
- 화해의 향후 제품 로드맵과 내부 KPI는 모른다.
- 공식 리디자인 의뢰나 상표 사용 허가 여부는 모른다.

위 항목은 추정하지 않는다. 포트폴리오 및 프로토타입 단계에서는 자체 데모 데이터와 공공 API만 사용한다.

## 3. 통합 전략

### 3.1 화해에서 유지할 자산

| 자산 | 유지 이유 | 리디자인 원칙 |
|---|---|---|
| 대규모 제품 탐색 | 서비스 진입의 핵심 | 검색·카테고리·랭킹 경로를 단순화 |
| 실사용 리뷰 | 구매 신뢰의 중심 | 리뷰 출처와 사용자 유사도를 먼저 표시 |
| 전성분 정보 | 제품 비교의 기준 | 성분 목록을 역할·주의·근거 단위로 해석 |
| 피부/나이/고민 랭킹 | 빠른 발견에 유용 | 집계 기간·모수·변동 이유를 함께 표시 |
| 쇼핑 | 정보 탐색을 구매로 연결 | 가격·혜택·배송·반품을 결정 카드에 통합 |
| 샘플 체험 | 구매 리스크 감소 | ‘먼저 써보기’를 정식 의사결정 경로로 배치 |

### 3.2 BE:CAUSE에서 이어갈 자산

| 기존 BE:CAUSE 기능 | 통합 후 역할 | 처리 |
|---|---|---|
| 스킨 차트 | 개인화 입력과 변화 기록 | 유지·고도화 |
| 피부 날씨 | 오늘의 환경 맥락 | 유지하되 홈 보조 모듈로 축소 |
| 성분 백과 | 성분 근거 탐색 | 제품 상세 및 통합 검색에 병합 |
| 루틴 빌더 | 구매 후 사용 경험 | 핵심 기능으로 승격 |

| 구매·관심·연령 랭킹 | 랭킹 출처 다양화 | 유지하되 기준·기간 표시 |
| 레미 AI 약사 | 맥락형 Q&A | 전역 플로팅 버튼 대신 필요한 지점에서 호출 |
| 화장품 법령 데이터 | 정보 신뢰와 최신성 | ‘근거 및 주의’ 패널에서 출처 제공 |
| 상품/장바구니/배송 | 커머스 흐름 | 데이터·결제 백엔드 준비 전 데모로 유지 |

### 3.3 핵심 차별화: Decision Stack

모든 제품 상세와 추천 카드에 다음 5개의 근거를 같은 구조로 제공한다.

1. **Fit** — 내 피부 타입·고민·알레르기 및 민감 이력과의 관련성
2. **Proof** — 나와 유사한 사용자의 리뷰 요약과 표본 크기
3. **Formula** — 핵심 성분 역할, 주의 조합, 기능성 정보
4. **Context** — 현재 날씨·계절·기존 루틴과의 관계
5. **Value** — 가격, 용량, 할인, 배송, 샘플 여부

단일 궁합 점수는 요약값일 뿐이며 반드시 위 5개 세부 근거로 펼쳐볼 수 있어야 한다.

## 4. 사용자와 핵심 과업

### 4.1 주요 사용자

#### A. 탐색 피로형

- 정보는 많이 보지만 무엇을 믿어야 할지 판단하기 어렵다.
- 핵심 과업: 짧은 시간 안에 후보 제품 2~3개를 만들기

#### B. 민감·문제 피부형

- 성분과 리뷰를 꼼꼼히 확인하고 실패 구매를 피하려 한다.
- 핵심 과업: 주의 성분, 유사 피부 리뷰, 루틴 충돌 확인

#### C. 성분 학습형

- 유행 성분보다 자신에게 필요한 이유를 알고 싶다.
- 핵심 과업: 성분의 역할·근거·함께 쓰는 법을 이해하기

#### D. 루틴 관리형

- 여러 제품을 가지고 있지만 순서와 조합이 불명확하다.
- 핵심 과업: AM/PM 루틴을 만들고 사용 결과를 기록하기

#### E. 비교 구매형

- PC의 넓은 화면에서 가격·리뷰·성분을 동시에 비교한다.
- 핵심 과업: 저장한 후보를 표로 비교하고 모바일에서 구매 계속하기

## 5. 서비스 구조

### 5.1 공통 콘텐츠 모델

서비스는 화면이 아니라 다음 여섯 도메인을 기준으로 설계한다.

1. **Discover** — 검색, 스캔, 랭킹, 브랜드, 에디토리얼
2. **Evaluate** — 상품 상세, 리뷰, 성분, 비교, 적합 근거
3. **Buy** — 가격, 혜택, 샘플, 장바구니, 주문, 배송
4. **Use** — AM/PM 루틴, 조합 주의, 사용 알림
5. **Track** — 피부 차트, 환경, 사용 기록, 변화 리포트
6. **Ask** — 레미의 제품·성분·루틴 설명

### 5.2 모바일 앱 IA

하단 내비게이션은 5개로 제한한다.

| 탭 | 목적 | 주요 화면 |
|---|---|---|
| HOME | 오늘의 개인화 요약 | 피부 브리프, 랭킹 3종, 루틴 알림, 최근 본 제품 |
| DISCOVER | 제품과 성분 발견 | 통합 검색, 랭킹, 카테고리, 브랜드, 성분 |
| SCAN | 현장에서 빠른 조회 | 바코드, 제품명, 전성분 OCR, 최근 스캔 |
| SHOP | 탐색에서 구매까지 | 큐레이션, 상품 목록, 샘플, 장바구니, 주문 |
| MY | 내 데이터와 루틴 | 스킨 차트, 루틴, 저장, 리뷰, 주문, 설정 |

`레미`는 고정 하단 탭으로 두지 않는다. 제품 상세의 “이 제품 물어보기”, 성분 상세의 “조합 물어보기”, 루틴의 “충돌 확인”처럼 문맥형 액션으로 제공한다.

### 5.3 웹사이트 IA

웹은 탐색 깊이와 비교 효율을 우선한다.

| 1차 메뉴 | 2차 구조 |
|---|---|
| Products | 전체 제품, 카테고리, 브랜드, 신규 등록 |
| Rankings | 구매, 관심, 피부 타입, 나이대, 급상승 |
| Ingredients | 성분 백과, 기능별 탐색, 조합, 최신 규정 |
| Reviews | 리뷰 검색, 피부 유사도, 리뷰 토픽, 리뷰 정책 |
| Compare | 최대 4개 제품 비교, 저장한 비교표 |
| Shop | 기획전, 샘플, 혜택, 장바구니, 주문 |
| My Beauty | 스킨 차트, 루틴, 기록, 저장, 주문 |

웹 홈은 앱 홈을 크게 확대한 형태가 아니라 `통합 검색 + 랭킹 신호 + 최근 데이터 + 깊은 비교 진입` 중심으로 별도 구성한다.

## 6. 핵심 화면 기획

### 6.1 온보딩과 스킨 프로필

- 필수 입력: 피부 타입, 주요 고민 1~3개, 민감 여부
- 선택 입력: 알레르기·피하고 싶은 성분, 연령대, 현재 루틴, 위치
- 모든 선택 입력은 건너뛸 수 있어야 한다.
- 프로필 완성률보다 추천 품질에 어떤 정보가 필요한지를 설명한다.
- 피부 사진은 별도 동의 후 선택적으로만 사용한다.

### 6.2 HOME — Daily Beauty Brief

한 화면에 모든 기능을 노출하지 않고 오늘 필요한 결정을 우선한다.

1. 오늘의 피부 맥락: 기온·습도·UV·미세먼지와 한 줄 행동 제안
2. 루틴 상태: 오늘 사용할 제품과 주의 조합
3. 신뢰 기반 랭킹 3종:
   - 구매 순위
   - 관심 순위
   - 내 나이대 순위
4. 최근 본 제품의 가격·랭킹 변화
5. 스킨 차트 기록 CTA

### 6.3 통합 검색

하나의 검색창에서 제품, 브랜드, 성분, 피부 고민, 리뷰 키워드를 찾는다.

- 입력 중 엔티티별 자동완성
- 결과 상단에 `제품 / 성분 / 브랜드 / 리뷰` 탭
- 오타·한글/영문 성분명·INCI 동의어 지원
- 검색 결과가 없을 때 제품 등록 요청 및 유사어 제안
- 웹에서는 최근 검색과 비교 목록을 우측 패널에 유지

### 6.4 랭킹

모든 랭킹 카드에 다음을 표시한다.

- 집계 기준: 구매, 저장, 조회, 리뷰, 연령, 피부 타입
- 집계 기간: 일간, 주간, 월간
- 표본 크기와 업데이트 시각
- 광고/프로모션 포함 여부
- 전주 대비 순위 변화 이유

랭킹은 “추천”이 아니라 “집계된 행동 신호”로 설명한다.

### 6.5 상품 상세 — Decision Stack

상단에서 바로 결정할 수 있는 정보:

- 상품명, 브랜드, 용량, 가격, 혜택, 배송
- 저장, 비교, 샘플 체험, 장바구니, 구매
- 궁합 요약 및 근거 5개

상세 탭:

1. Overview — 핵심 요약과 추천/주의 이유
2. Reviews — 유사 피부 우선, 긍정·아쉬움 토픽, 출처 필터
3. Ingredients — 전성분, 역할, 주의, 법적 고지
4. Routine — 현재 루틴과 중복·충돌·사용 순서
5. Price — 옵션, 가격 이력, 쿠폰, 배송·반품

### 6.6 리뷰

- `실구매`, `일반`, `체험단`, `브랜드 제공` 배지를 시각적으로 분리
- 사용자와 리뷰 작성자의 피부 유사 조건 표시
- AI 요약은 원문 링크와 표본 수를 반드시 함께 제공
- 긍정/부정 이분법 대신 제형·흡수·자극·보습·향 등 토픽으로 탐색
- 리뷰 작성 시 사용 기간과 제품 사용 맥락을 받는다.

### 6.7 성분 백과

- 한글명, 영문명, INCI, 동의어
- 배합 목적과 일반적 역할
- 기능성·주의·알레르기 관련 정보
- 함께 쓰기 좋은 조합과 주의할 조합
- 관련 제품과 내 루틴 포함 여부
- 데이터 출처와 최근 확인일

‘좋은 성분/나쁜 성분’으로 단정하지 않고 농도·제형·피부 상태에 따라 달라질 수 있음을 명확히 한다.

### 6.8 제품 비교

- 모바일: 최대 3개, 핵심 차이만 카드로 비교
- 웹: 최대 4개, 고정 첫 열을 가진 비교표
- 비교 항목: 가격/용량, 리뷰 신뢰, 내 피부 근거, 핵심 성분, 주의, 루틴 중복, 배송
- 차이가 없는 행은 접고 중요한 차이를 먼저 강조
- 비교표를 링크로 저장하고 앱에서 계속 볼 수 있도록 한다.

### 6.9 스킨 차트와 루틴

- 스킨 차트: 건조감, 유분감, 민감도, 트러블, 탄력 등 자기 보고 기반
- 얼굴 이미지는 진단 결과가 아니라 기록 진입을 위한 에디토리얼 비주얼로 사용
- AM/PM 루틴에 제품 등록, 순서 조정, 사용 요일 설정
- 성분 중복이나 주의 조합은 경고 강도를 구분
- 2~4주 뒤 사용 전후 변화를 같은 질문으로 다시 기록

### 6.10 레미

레미는 의료 전문가를 흉내 내는 챗봇이 아니라 **화장품 정보 해설자**다.

- 가능한 것: 성분 용어 설명, 제품 차이 요약, 리뷰 토픽 정리, 루틴 사용 순서 안내
- 불가능한 것: 질환 진단, 치료·약물 처방, 안전을 보장하는 확정 표현
- 모든 답변에 근거 링크와 데이터 날짜 제공
- 건강 위험 신호는 상담 중단 후 의료기관/전문가 안내

## 7. 모바일과 웹의 역할 분담

| 과업 | 모바일 우선 | 웹 우선 |
|---|---|---|
| 매장에서 제품 조회 | 바코드·OCR 스캔 | 해당 없음 |
| 오늘의 루틴 확인 | 빠른 카드와 알림 | 월간 기록 확인 |
| 제품 검색 | 음성·최근 검색·짧은 결과 | 다중 필터·넓은 결과표 |
| 리뷰 보기 | 한 손 스크롤·필터 시트 | 토픽 분포와 긴 리뷰 분석 |
| 제품 비교 | 핵심 차이 3개 | 최대 4개 상세 비교표 |
| 구매 | 간편 결제와 배송 추적 | 옵션·혜택·정책 상세 확인 |
| 스킨 차트 | 사진/자가 기록 | 변화 그래프와 기록 내보내기 |

계정, 저장 목록, 비교 목록, 장바구니, 루틴은 양쪽에서 동기화한다.

## 18. 홈페이지 디자인 시안 방향 · 2026-08-28

공통 원칙: `BE:CAUSE`를 제품명으로 사용하고, 공식 협업 전에는 `Unofficial redesign concept`를 표기한다. 페일 블루 배경, 네이비 에디토리얼 타이포, 투명 스킨 렌즈, 프로스티드 글라스 데이터 레일을 공통 언어로 사용한다. 형광 라임은 근거의 최신성·신뢰·변화 신호에만 제한한다.

### A. Decision Atlas

- 목적: 처음 방문한 사용자가 오늘의 피부 맥락과 구매 근거를 한 화면에서 빠르게 이해한다.
- 구조: 통합 검색 → 개인 피부 컨텍스트 → 추천 제품 → 하단 4분할 근거 레일 → 구매·관심·나이대 랭킹.
- 강점: Decision Stack의 `Fit / Proof / Routine / Value`를 가장 명료하게 소개한다.

### B. Review Atlas

- 목적: 실구매 리뷰의 신뢰와 유사 피부 반응을 서비스의 첫인상으로 만든다.
- 구조: 실사 피부 이미지와 스킨 렌즈 → 검증 리뷰 카드 3개 → 리뷰 토픽·언급 성분·관련 제품·데이터 신선도 레일.
- 강점: 광고성 추천보다 반응 근거를 우선하는 리뷰 탐색의 차별점이 뚜렷하다.

### C. Context Gallery

- 목적: 구매 전 정보와 구매 후 루틴·기록이 하나의 흐름임을 보여준다.
- 구조: AM→PM 루틴 타임라인 → 환경 컨텍스트 카드 → 저장 제품·스킨 저널·비교 트레이·문맥형 Remi 진입.
- 강점: 앱의 루틴/스킨 차트와 웹의 비교 경험을 자연스럽게 연결한다.
